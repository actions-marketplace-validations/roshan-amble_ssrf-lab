## Separate audit failure

The unchanged pinned consumer does **not** pass its full `npm run quality`
command. In [the initial run](https://github.com/roshan-amble/ssrf-lab/actions/runs/39288114368),
that command stopped at the development-dependency audit on both runtimes.
The preceding production-dependency audit reported zero vulnerabilities.

The successful request workflow records that same audit baseline separately:
exit code 1 on both runtimes, with a visible workflow warning. Audit status does
not gate the request trial. See [Node 22 audit output](node22-consumer-audit.txt)
and [Node 24 audit output](node24-consumer-audit.txt), with machine-readable
statuses [here](node22-consumer-audit.json) and [here](node24-consumer-audit.json).
No consumer source, dependency manifest or lockfile was modified.

The tested address fixtures do not establish DNS-rebinding resistance, TLS
security, protection for every private destination, parser correctness, or
resource-limit coverage. `preview()` does not expose the raw response body;
the request counters provide the reach evidence. See the
[trial documentation](../../../integrations/linkpeek/README.md) for scope and
reproduction steps.
